先在左侧找到“我看见了什么”，读浅白解释，然后才认识正式名称。最后一列带你回到这个词首次展开的教学位置。解释是入口，不代表只靠一句话就能判断所有真实网络；地址、端口和协议还要结合所在层次一起看。

## 先修实验里看得到的东西

| 看到的现象                                  | 浅白解释                                                                   | 正式术语                         | 首次教学                                     |
| ------------------------------------------- | -------------------------------------------------------------------------- | -------------------------------- | -------------------------------------------- |
| 在屏幕里打开页面                            | 接收并显示网页内容的应用；它不是所有网页服务本身。                         | 浏览器                           | [浏览器与程序](/basics/browser-and-programs) |
| 桌面图标打开以后有东西在工作                | 程序是可执行的一组指令；运行中的一个实例叫进程。                           | 程序 / 进程                      | [浏览器与程序](/basics/browser-and-programs) |
| 关闭 Python 终端里的实验，网页就无法再请求  | 一台电脑上可以有多个独立进程，停止其中一个不自动停止其他进程。             | 服务进程                         | [自己电脑上的网页](/basics/local-webpage)    |
| 地址栏里有 http、地址、冒号和斜杠           | 网址中分别写协议、主机、可选端口和资源路径等部分。                         | URL / 网址                       | [读一个网址](/basics/read-a-url)             |
| 输入 localhost 就在联系本机                 | 代表本机的特殊名称，系统可能得到 IPv4 127.0.0.1 和 IPv6 ::1。              | localhost                        | [读一个网址](/basics/read-a-url)             |
| 127.0.0.1 的系统路由显示 lo0                | 回环是电脑内部的网络路径，lo0 是 macOS 本次看到的回环接口名称。            | 回环接口 / lo0                   | [我电脑里的网络](/basics/my-network)         |
| 系统设置里看见 Wi-Fi，EasyTier 又有 utun    | 接口是系统收发网络数据的入口，可以是原有设备接口或虚拟接口。               | 网络接口 / 网卡                  | [我电脑里的网络](/basics/my-network)         |
| 同一主机名得到 127.0.0.1 与 ::1 两种写法    | IPv4 和 IPv6 是两种 IP 地址协议；监听其中一种不自动证明另一种也可用。      | IPv4 / IPv6                      | [读一个网址](/basics/read-a-url)             |
| 浏览器点击链接，终端多了一行 GET            | 浏览器向服务询问资源叫请求，服务交回状态与内容叫响应。                     | 请求 / 响应                      | [观察一次请求](/basics/observe-a-request)    |
| Network 出现 200 或 404                     | 服务已经用 HTTP 回答；状态码说明本次请求的处理结果。                       | HTTP 状态码                      | [观察一次请求](/basics/observe-a-request)    |
| 404 和连接失败的画面不同                    | 404 是服务回答没有资源；连接失败还没有获得该服务的正常 HTTP 答复。         | 应用错误 / 连接失败              | [观察一次请求](/basics/observe-a-request)    |
| 网页里复制的 10.144 地址不是自己设备的读数  | 公开讲解可替换私人地址；示例数字不能冒充实际观察，也不能直接拿去探测。     | 教学地址 / 脱敏                  | [我电脑里的网络](/basics/my-network)         |
| Wi-Fi 地址、EasyTier 地址和外部端口同时出现 | 分别用于原有网络、本教程虚拟业务网络、底层隧道搬运；不能互相当作同一地址。 | 原有网络 IP / 虚拟 IP / 隧道端点 | [我电脑里的网络](/basics/my-network)         |

## 数据与应用

| 看到的现象                                   | 浅白解释                                                                           | 正式术语   | 首次教学                                  |
| -------------------------------------------- | ---------------------------------------------------------------------------------- | ---------- | ----------------------------------------- |
| 两边要按相同规则才能听懂彼此                 | 通信双方共同遵守的规则，包括数据怎样表示、怎样交换以及遇到错误怎样处理。           | 协议       | [数据包](/chapters/02-packets)            |
| 一个网页请求在网络里分成多块传送             | 传输中的一块数据及其必要说明；一个请求可以拆成多个包，一个包也可能丢失。           | 数据包     | [数据包](/chapters/02-packets)            |
| 网址、TCP 端口、IP 和网卡各做不同工作        | 把应用、传输、地址和实际搬运分开处理，让不同职责有清楚的交接位置。                 | 分层       | [数据包](/chapters/02-packets)            |
| 网页连接会等待、确认并补发缺失数据           | 给应用提供可靠、有序的字节流，会处理确认、重传和拥塞；不保证网络永不失败。         | TCP        | [协议与端口](/chapters/04-protocols)      |
| GUI 显示 UDP，却仍可以搬运 TCP 网页          | 以数据报方式交付数据，不由协议本身保证可靠和有序；上层可以另做可靠传输。           | UDP        | [协议与端口](/chapters/04-protocols)      |
| 同一个地址，换 8877 和 8080 会联系不同服务   | 与 IP、协议配合识别通信端点的编号；服务监听端口与临时源端口用途不同。              | 端口       | [读一个网址](/basics/read-a-url)          |
| 不只写端口，还要写谁从哪里联系谁、用什么协议 | 源 IP、源端口、目标 IP、目标端口和协议的组合，用于描述一条具体通信关系。           | 五元组     | [协议与端口](/chapters/04-protocols)      |
| Python 开着时能联系，停止后不能联系          | 服务向操作系统登记接收新连接的地址、协议和端口；只监听回环地址通常不能被远端访问。 | 监听       | [自己电脑上的网页](/basics/local-webpage) |
| 127.0.0.1 的网页只在我这台电脑里走           | 代表本机内部的地址，例如 `127.0.0.1`；A 访问自己的回环地址不会连接到 B。           | 回环地址   | [自己电脑上的网页](/basics/local-webpage) |
| Network 里看见请求、200 或 404 回答          | 浏览器和网页服务常用的应用协议；得到 HTTP 错误答复和无法建立连接是不同阶段。       | HTTP       | [观察一次请求](/basics/observe-a-request) |
| 输入名字时，需要先知道它对应哪个地址         | 把名称查询为地址等记录的系统；解析正确不会自动解决路由、监听或权限问题。           | DNS        | [读一个网址](/basics/read-a-url)          |
| 有些应用会自动找 LAN 设备，虚拟网里却找不到  | 向一组接收者发送数据的方式；三层虚拟网络可达不代表局域网自动发现协议一定可用。     | 广播与组播 | [应用与 DNS](/chapters/17-apps-dns)       |

## 地址、路由与边界

| 看到的现象                                 | 浅白解释                                                                     | 正式术语 | 首次教学                              |
| ------------------------------------------ | ---------------------------------------------------------------------------- | -------- | ------------------------------------- |
| 电脑上同时出现回环、Wi-Fi 和虚拟网络的地址 | 网络层用于标识接口并选择目的地的地址；一台设备可以同时拥有多个接口与地址。   | IP 地址  | [我电脑里的网络](/basics/my-network)  |
| 不同家庭都可能有 192.168 开头的地址        | 留给内部网络使用的地址，很多不同家庭可重复使用；不能单靠它在公网定位设备。   | 私有地址 | [地址与网段](/chapters/03-addresses)  |
| 对外通信使用公共网络中的地址               | 可以在公共网络中使用的地址；拥有它仍需正确监听与放行，才可能接受连接。       | 公网地址 | [NAT](/chapters/06-nat)               |
| 地址后面出现 /24，表示一组地址范围         | 由一段共同的地址前缀表示的一组地址，例如 `192.168.20.0/24`。                 | 网段     | [地址与网段](/chapters/03-addresses)  |
| 192.168.20.0/24 中斜杠后的数字不是端口     | 用地址加前缀长度表示网段的方法；`/24` 表示前 24 位是网络前缀，不是端口号。   | CIDR     | [地址与网段](/chapters/03-addresses)  |
| 同一个系统对不同目标选择不同接口           | 指导系统或节点把目标地址交给哪个接口、网关或下一跳的规则集合。               | 路由表   | [我电脑里的网络](/basics/my-network)  |
| 访问非本地网段时，先交给下一站             | 帮设备把数据送往其他网络的下一站；局域网默认网关未必知道虚拟网段在哪里。     | 网关     | [我电脑里的网络](/basics/my-network)  |
| 更具体规则没匹配时，仍有一个通常采用的方向 | 没有更具体匹配时采用的路由；改变它可能影响大量互联网流量。                   | 默认路由 | [路由](/chapters/05-routing)          |
| 经过 R 时，下一站和最终 B 不是同一台       | 当前节点准备把数据交给的下一站，不一定是业务的最终目标。                     | 下一跳   | [拓扑](/chapters/14-topology)         |
| 请求到了，但回答还得正确返回               | 响应返回发起者的路径；去程能到达，不能自动证明回程正确。                     | 回程     | [子网代理](/chapters/16-subnet-proxy) |
| 家里多台电脑借边界设备的外部地址通信       | 在边界上修改地址或端口并维护对应关系的机制，常用于多个私网设备共享外部地址。 | NAT      | [NAT](/chapters/06-nat)               |
| 内部地址端口和外部地址端口形成对应关系     | 内部端点与外部端点的对应关系；不同目的地是否共用映射影响打洞。               | NAT 映射 | [NAT](/chapters/06-nat)               |
| 有映射不等于任意来源都能进来               | 判断哪些外部来源可以进入已有映射的规则；应与映射规则分别理解。               | NAT 过滤 | [打洞](/chapters/11-hole-punch)       |
| 进程在运行，规则仍可能不允许请求           | 按规则允许或拒绝流量的机制；外层隧道端口与内层应用端口需要分别检查。         | 防火墙   | [应用与 DNS](/chapters/17-apps-dns)   |
| 只允许某些来源访问某些目标或端口           | 访问控制列表，按来源、目标、协议、端口等条件表达谁可以访问什么。             | ACL      | [应用与 DNS](/chapters/17-apps-dns)   |

## EasyTier 的结构与连接

| 看到的现象                                  | 浅白解释                                                                      | 正式术语         | 首次教学                                |
| ------------------------------------------- | ----------------------------------------------------------------------------- | ---------------- | --------------------------------------- |
| 用 EasyTier 地址访问原本不在同一 LAN 的节点 | 建在现有网络之上的通信网络，使应用可以通过虚拟地址访问远方节点。              | 虚拟网络         | [为什么需要 EasyTier](/chapters/01-why) |
| 虚拟包仍需要 Wi-Fi、家庭网络和互联网搬运    | 实际承载数据的底层网络，包括 LAN、路由器与互联网链路。                        | Underlay         | [TUN](/chapters/07-tun)                 |
| 应用使用另一套虚拟地址和节点路由            | 利用底层网络建立的上层网络；EasyTier 的虚拟节点和路由属于这一层。             | Overlay          | [TUN](/chapters/07-tun)                 |
| 目标虚拟 IP 的路由指向 utun 等虚拟接口      | 向程序提供三层 IP 包的虚拟网络接口，连接操作系统路由与用户态隧道程序。        | TUN              | [TUN](/chapters/07-tun)                 |
| 业务包通过另一层连接到远端                  | 把原来的数据放进另一层传输，再在目的端处理和取出的通信方式。                  | 隧道             | [完整请求](/chapters/15-journey)        |
| 外层运输信息包着原来的业务数据              | 给原始数据加上外层说明，便于另一层网络搬运；它通常增加包大小。                | 封装             | [完整请求](/chapters/15-journey)        |
| GUI 列出正在联系的网络节点                  | 虚拟网络中的对等节点；节点身份不应仅靠一个显示主机名判断。                    | Peer             | [成员关系](/chapters/09-membership)     |
| 两台节点用匹配成员配置进入同一网络          | 本教程组网示例使用的成员配置，需按组网方式匹配；不是 HTTP 应用登录密码。      | 网络名与网络密钥 | [成员关系](/chapters/09-membership)     |
| 启动先联系一个入口，以便知道其他节点        | 启动时先连接的节点，帮助设备进入网络；它不必承担所有后续业务中转。            | 初始节点         | [启动](/chapters/08-startup)            |
| 程序询问外部看到的地址和端口                | 帮助发现外部端点等 NAT 行为信息的协议；不负责替对方打开防火墙。               | STUN             | [STUN](/chapters/10-stun)               |
| 双方尝试主动发包建立直接关系                | 利用双方主动发包和映射信息尝试建立直接通信的过程，不保证所有网络都成功。      | NAT 打洞         | [打洞](/chapters/11-hole-punch)         |
| 目标 B 行显示 p2p                           | 两个目标节点之间直接建立通信关系；查看状态时必须先确认是对哪个节点。          | P2P / 直连       | [排障](/chapters/19-diagnostics)        |
| 目标需由 R 等其他节点继续搬运               | 由其他节点继续搬运发往目标的流量；可补充可达性，但有链路和资源成本。          | 中转             | [中转](/chapters/13-relay)              |
| 网络中有多种相邻关系和可用路径              | 节点形成可互相联系的网络结构，不等于每两个节点都有直接隧道。                  | Mesh             | [拓扑](/chapters/14-topology)           |
| A 到 B 的路径中有多段节点连接               | 数据通过多个相邻节点连接到达目标；跳数不是中间节点数量。                      | 多跳             | [拓扑](/chapters/14-topology)           |
| 经过 B 访问没装 EasyTier 的 LAN 设备 H      | 一个节点把自己能访问的网段共享给虚拟网络，通过它访问未安装 EasyTier 的设备。  | 子网代理         | [子网代理](/chapters/16-subnet-proxy)   |
| 由系统继续把包从一个接口交到另一个接口      | 由操作系统处理跨接口转发；启用相应模式后，转发规则与回程需要明确设计。        | 系统转发         | [子网代理](/chapters/16-subnet-proxy)   |
| 把其他节点的一般外部访问带到自己的出口      | 为其他节点提供外部网络访问出口的节点，和访问某个远端 LAN 的子网代理用途不同。 | 出口节点         | [子网代理](/chapters/16-subnet-proxy)   |
| 确认谁在通信，以及保护传送的内容            | 认证帮助确认身份，加密保护内容；两者不能替代应用层权限设计。                  | 认证与加密       | [安全](/chapters/12-security)           |

## 性能与观察

| 看到的现象                               | 浅白解释                                                                | 正式术语  | 首次教学                         |
| ---------------------------------------- | ----------------------------------------------------------------------- | --------- | -------------------------------- |
| ping 每一行出现 time=… ms                | 一次数据往返所需的时间，包含两个方向和相关处理，不是单向延迟。          | RTT       | [性能](/chapters/18-performance) |
| 宽带标称容量不等于一次文件下载速度       | 链路能搬运数据的容量；它不等于当前应用已经达到的速度。                  | 带宽      | [性能](/chapters/18-performance) |
| 一段时间实际收到了多少有效数据           | 一段时间实际完成的数据传输量，受到协议开销、链路、丢包及系统处理影响。  | 吞吐量    | [性能](/chapters/18-performance) |
| 发出四次请求，却只收到部分回应           | 发出的包未按预期到达，需要结合路径和应用处理判断原因及影响。            | 丢包      | [性能](/chapters/18-performance) |
| 接口显示 1360，小包和大包表现可能不同    | 接口或路径能承载的 IP 包大小上限；隧道封装后需留出额外空间。            | MTU       | [性能](/chapters/18-performance) |
| 某些 TCP 流可以改用另一种可靠搬运方式    | EasyTier 用 KCP 搬运 TCP 流的能力，某些丢包环境可能受益，也有重传成本。 | KCP 代理  | [性能](/chapters/18-performance) |
| TCP 流被代理搬运，但网页未必变成 HTTP/3  | EasyTier 用 QUIC 搬运 TCP 流的能力，不等于应用自动使用 HTTP/3。         | QUIC 代理 | [性能](/chapters/18-performance) |
| CLI 查询不到本机管理入口，隧道却未必断开 | CLI 与本机 core 交换管理信息的接口；查询失败不必然表示远端隧道失败。    | 管理 RPC  | [排障](/chapters/19-diagnostics) |

没有找到现象时，先回[零基础入口](/basics/browser-and-programs)或[学习路线](/course)。想核对正式定义与版本行为，再读[资料来源](/sources)。
